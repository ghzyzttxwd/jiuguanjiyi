# 变量归档桥 / Variable Archive Bridge

版本：0.1.1

这是一个 **SillyTavern 通用 MVU 变量生命周期管理扩展**。它不属于任何一张角色卡，也不理解“人物/武功/世界”这些业务语义；它只处理你明确指定的 `stat_data` JSON 路径。

## 它解决什么问题

长期变量卡会自然出现：

- 世界档案越来越多
- 人物越来越多
- 武功/能力/装备越来越多
- `stat_data` 越来越大，每轮都重复进入 Prompt

本扩展把 MVU 当作“热内存”，把暂时不用的数据放进浏览器 IndexedDB 冷存储，需要时再恢复。

## V0.1.1 功能

- 自动检测当前聊天最新 MVU `stat_data`
- 显示变量体积、节点数
- 为任意角色卡配置“归档容器”JSON Pointer，例如 `/世界档案`、`/长期人物`、`/玩家/能力`
- 只允许归档“已配置容器的直接子项”
- 手动归档 / 恢复
- 每次归档前自动保存完整变量快照
- 定时变量快照、快照恢复
- 导入/导出当前聊天的冷档案与快照
- `{{varArchiveContext}}` 按需注入宏
- 可选兼容“记忆增强表格”插件
- 实验性自动归档（默认关闭）

## 安全设计

1. **不会自动扫描后随便删变量。** 只有你明确添加为归档容器的路径，才有资格卸载其直接子项。
2. **默认关闭自动归档。** 建议先手动使用一段时间。
3. **每次归档前强制快照。**
4. **完整原始数据先写 IndexedDB，再修改 MVU。**
5. 如果 MVU Schema 将被删除节点自动补回，插件会验证并报错，不会假装成功。
6. 当前MVU与冷档案冲突时，**MVU优先**。

## 安装

SillyTavern 的第三方扩展通常从 Git 仓库安装。当前压缩包是本地测试版：

- 解压 `variable-archive-bridge` 整个文件夹到 SillyTavern 的第三方扩展目录；或
- 将这个文件夹放进你自己的 GitHub/Gitee 仓库，再在“扩展 → 安装扩展”填仓库地址。

安装后刷新酒馆，在“扩展”设置区会看到 **📦 变量归档桥**。

## 最短使用路径

1. 打开一张已经正常运行 MVU 的变量卡。
2. 扩展 → 变量归档桥。
3. 先确认状态显示“MVU ●”。
4. 添加一个确实是动态字典/record的路径，例如：
   - `/世界档案`
   - `/长期人物`
   - `/玩家/能力`
5. 先点“保存变量快照”。
6. 在路径下挑一个确实暂时不用的子项 → “归档”。
7. 确认卡仍能正常跑几轮。
8. 需要时点“恢复”。

> 不要把固定必需对象路径（例如 `/玩家`、`/当前世界` 整个对象）作为归档容器。优先选择 z.record / 动态对象容器。

## Kemini Dramatron 接入

你的 Kemini 预设有“💠自定义缝合处”，它位于 `<DATA>` 结束之前。把下面一行填进去即可：

```text
{{varArchiveContext}}
```

宏的规则：

- 只取“置顶档案”以及“最近两条用户消息命中”的冷档案；
- 如果同一路径数据已经存在当前 MVU，则绝不重复注入；
- 已镜像到记忆增强表格的记录默认不再由此宏重复注入；
- 有总字符上限和最大档案数。

因此它不会把整个冷数据库每轮都塞给模型。

## 记忆增强表格兼容

记忆增强表格不是必需依赖。本扩展即使它关闭，也能独立归档和恢复。

如果启用“镜像到记忆增强表格”，请自行创建一个 7 列表格，列顺序：

1. 档案ID
2. 聊天
3. 变量路径
4. 子键
5. 摘要
6. 压缩JSON
7. 更新时间

然后在本扩展填写对应 **表格索引**。

镜像只负责让长期记忆表格能看见一份摘要/压缩数据；**完整权威冷档仍在本扩展 IndexedDB**。

如果记忆增强表格本身已经把这些行注入 Prompt，请不要同时让 `{{varArchiveContext}}` 重复注入同一批资料。默认设置已经避免“已镜像记录”的重复注入。

## 自动归档

V0.1.1 已实现但总开关默认关闭。

每个归档容器可设置：

- 子项上限
- 保留最近多少项
- 至少闲置多少条消息
- 是否允许自动归档

自动归档一次最多卸载一个子项，并先保存快照。

## 数据位置与备份

- 冷档与快照：浏览器 IndexedDB 数据库 `variable_archive_bridge`
- 设置与路径策略：LocalStorage

IndexedDB 不会自动跨设备同步。长期使用务必定期点“导出当前档案”。

## V0.1.1 不做的事

- 不做新的向量数据库
- 不替代记忆增强表格
- 不自动让AI决定哪些人物/技能“应该删除”
- 不自动恢复被提及对象到 MVU（目前只提供 Prompt 按需注入 + 手动恢复）
- 不跨设备同步

这些等 V0.1.1 手机端真实运行稳定以后再做。


## V0.1.1 工程修正

- 强制快照现在会在手动/自动归档和恢复前真实执行，不会被 busy 锁跳过。
- 自动归档不会在“无需归档”时误卸载一项。
- 自定义宏优先使用 SillyTavern Macro Engine 2.0 的 `macros.register()`，并保留旧版 `registerMacro()` 回退。
- 增加旧 Android WebView 的 CSS 选择器转义回退。
