# Variable Archive Bridge 智能托管安全重构 RC4

## 事故根因
旧 `smart_host.js` 使用 `MutationObserver` 监听整个 `document.documentElement` 子树，同时 `patchPanel()` 又持续写入 DOM。DOM 写入再次触发同一个 Observer，形成自触发循环，最终占满移动端 WebView 主线程并卡在加载齿轮页。

## 当前隔离状态
- 正式插件仍维持 **v0.1.4**。
- 正式启动链不直接导入任何智能托管实验模块。
- `experimental/smart_host_safe.js` 仅在用户显式点击“加载候选模块”后动态导入。
- 每次加载候选模块都会强制把 `enabled` 重置为 `false`。
- 重启 SillyTavern 后候选模块不会自动再次载入。
- `MutationObserver` 在正式/候选 UI 代码中均被 CI 明确禁止。

## RC4 核心改动：去掉自动轮询归档
RC3 仍有每15秒检查一次的归档循环。RC4 已删除该模式，改成**事件驱动**：
- 监听 SillyTavern 的生成开始/结束、角色消息渲染、消息接收、消息更新、聊天切换事件；
- 生成开始时立即取消待执行任务；
- 生成期间绝不写 MVU；
- 仅在生成结束或稳定消息事件后延迟一次安全检查；
- 不存在 `CYCLE_INTERVAL_MS`，也不允许 `setInterval(...runCycle...)`；
- 卸载候选模块时通过 `eventSource.removeListener()` 清理所有事件监听。

UI 保活仍保留一个低频 `setInterval(ensureUi)`，它只在 VAB 面板重绘后重新插入候选 UI，不触发归档逻辑，也不会循环修改已存在的节点。

## 写入侧保险
自动托管真正写 MVU 前必须同时通过以下条件：
1. 总开关已开启；
2. 当前不在模型生成期；
3. 页面不是后台隐藏状态；
4. 当前聊天 scope 在刷新前后未变化；
5. 旧版“自动归档总开关”没有同时开启；
6. 聊天楼数达到最低阈值；
7. 容器达到动态容量阈值；
8. 候选对象闲置达到最低消息数；
9. 最近上下文/热状态没有引用该对象；
10. 同一聊天消息数下最多自动改1项；
11. 动作之间有30秒冷却；
12. 10分钟内累计3次异常自动熔断并关闭智能托管。

最终迁移继续调用已经实机验证的 VAB `archiveChild()` / `restoreArchive()`，沿用：

> 快照 → 写冷档案 pending → 修改 MVU → 重新读取验证 → 标记 archived

## 热对象保护
RC4 不再把整个 `/玩家` 子树都视为热数据，否则 `/玩家/武学` 会永久无法归档。

新增纯函数 `collectHotAnchorText()`：
- 读取“当前主修 / 当前目标 / 当前任务 / 队伍 / 小队 / 同行 / 正在使用 / 装备中 / 锁定目标”等热字段；
- 主动跳过“人物库 / 武学库 / 技能 / 物品 / 资产 / 世界档案 / 关系档案”等可能无限增长的大容器；
- 与最近8条双方聊天内容合并后，用于保护当前真正活跃的角色、武学、装备和任务对象。

因此类似：
- 当前主修 `武学60` → 保护；
- 当前队伍 `人物100/99/98` → 保护；
- 当前任务涉及 `人物97` → 保护；
- 人物库里的 `人物1` 若长期不再出现 → 仍可成为冷档案候选。

## 动态热区阈值
不再用“一律30项”处理所有容器：
- 小条目可以在热区保留更多；
- 单条几KB到十几KB的世界档案/复杂人物，会在较少数量时开始进入候选；
- 仍然一次只迁移1项，不会批量清空。

当前逻辑会根据容器总大小和平均单项大小计算 `effectiveMinChildren`。例如测试里的 9KB/条世界档案，动态热区下限为5；普通小物品仍保持基础上限30。

## 只读未来模拟
候选模块保留“模拟未来闲置60条”：
- 不修改真实 MVU；
- 不写 IndexedDB；
- 不修改活动记录；
- 在内存中虚拟扩张容器到触发线；
- 展示最多3个可能被归档的候选和对应动态热区阈值。
