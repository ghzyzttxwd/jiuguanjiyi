# Variable Archive Bridge 冷档案自动召回 RC1

## 目标
归档解决的是“MVU热变量越来越大”；召回解决的是“数据归档后，模型需要时怎么自动想起来”。

目标不是把冷档案一提到就全部恢复回 MVU，而是增加一层**只读读穿缓存**：

> 当前MVU + 最近聊天 → 检索相关冷档案 → 只把相关片段放进本轮Prompt → 冷档案继续留在IndexedDB

这样可以同时避免：
- 世界档案/人物/武学越玩越多把 stat_data 塞爆；
- 为了回忆一个旧角色，把整个人物库重新恢复成热变量；
- 用户手工去数据库找资料；
- 每轮把全部冷档案无脑塞进Prompt。

## RC1 架构
### 1. `recall_core.js`
纯逻辑、无 DOM、无 SillyTavern 写操作：
- 只处理 `status=archived` 的冷档案；
- 若同一个 pointer 已经存在于当前 `stat_data`，直接排除，防止热冷重复；
- 名称精确命中权重最高；
- 其次是标签、原变量路径、摘要命中；
- 可选把置顶档案作为低优先级常驻背景；
- 可在记忆增强启用时跳过 `mirroredToMemory` 档案，避免双重注入；
- 相同 pointer 去重；
- 默认最多6条；
- 默认总字符上限9000；
- 默认单条2600字符，超长JSON截断；
- 格式中明确声明：与当前MVU或最新剧情冲突时，以热变量/最新剧情为准。

### 2. `recall_safe.js`
实验 Prompt 适配层，默认关闭：
- 唯一 Prompt Key：`vab_cold_recall`；
- 实际注入默认关闭，且不持久化“开启”状态；
- 重载实验模块后重新回到关闭；
- 只读预览无需修改Prompt；
- 真正开启时通过 SillyTavern `getContext().setExtensionPrompt` 注入；
- Prompt 位置常量通过 `/script.js` 的 `extension_prompt_types.IN_PROMPT` 动态解析，不硬编码魔法数字；
- 监听消息发送/编辑、聊天切换、生成前组合Prompt事件；
- 聊天切换和卸载时清空自己名下的 Prompt；
- 所有事件监听卸载时 `removeListener`；
- 文件中不存在 `replaceMvuData`、`archiveChild`、`restoreArchive`，因此召回层本身没有修改 MVU 的权限路径。

## 检索上下文
查询文本由两部分组成：
1. 最近8条双方聊天；
2. `collectHotAnchorText(stat_data)` 生成的当前任务/队伍/主修/目标等热状态锚点。

因此：
- 用户说“降臣后来怎么样了” → 可以命中旧世界档案中的“降臣”标签；
- 当前任务重新提到某个旧人物，即使用户这一句没写名字，也可以通过热状态锚点召回；
- 已经恢复到热变量里的对象不会再从冷档案重复注入。

## 与记忆增强/宏的关系
RC1 只做候选，不替换现有正式功能。

当前原则：
- 完整原始冷数据：VAB IndexedDB；
- `st-memory-enhancement`：可选摘要镜像；
- `{{varArchiveContext}}`：现有手工宏通道；
- `vab_cold_recall`：新的自动读穿候选通道。

生产版最终只应保留一个主要的自动冷档案注入通道，避免宏与自动读穿重复发送同一档案。RC1 还没有并入正式启动链。

## 自动化验证
CI 已新增 `test_recall_core.mjs`，覆盖：
- 热变量同 pointer 排除；
- 冷档案名称强命中；
- 标签/路径/摘要召回；
- restored 记录排除；
- 置顶背景召回；
- 已镜像档案可配置排除；
- 多记录排序；
- pointer 去重；
- 总字符预算；
- 单档案截断；
- 冲突优先级说明存在。

工作流同时检查：
- `recall_safe.js` 语法；
- 不允许 MutationObserver；
- 实际注入默认关闭；
- 必须使用唯一 Prompt Key；
- 必须有 Prompt 清理逻辑和事件解绑；
- 召回适配层不得出现 MVU 写入/归档/恢复函数。
